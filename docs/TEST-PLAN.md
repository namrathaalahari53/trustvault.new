# TrustVault Test Plan — Beginner Friendly

Run the test groups after each feature, not only at the end.

## Authentication
- Correct login succeeds.
- Wrong password fails.
- Unknown email fails.
- Empty and malformed input fails validation.
- Inactive account cannot log in.
- Expired or malformed token receives 401.
- Password change requires correct current password.
- Temporary password must be changed according to policy.
- Repeated failed logins are rate-limited in production.

## Admin and users
- Admin creates Owner and Viewer.
- Duplicate email is rejected.
- Weak temporary password is rejected.
- Non-admin cannot call admin endpoints.
- Inactive user cannot access documents.
- Admin can review audit events.

## Upload and scanning
- Valid supported file is accepted.
- Empty, too-large and unsupported file is rejected.
- Spoofed MIME/extension is rejected after signature validation is implemented.
- Scanner unavailable means fail closed.
- Infected file remains quarantined.
- Upload attempt is audited.
- Storage file names are generated by server, not trusted from client.

## Read and download authorization
- Owner reads own clean document.
- Viewer reads document with active Read grant.
- Editor reads document with active Edit grant.
- Stranger receives denial.
- No token receives 401.
- Guessed ID does not reveal another user's document.
- Direct storage path is not public.
- Pending, rejected and scan-failed files cannot be read/downloaded.

## Edit and delete
- Owner can update metadata and delete own document.
- Editor can update only when explicitly granted Edit.
- Viewer cannot update.
- Stranger cannot update or delete.
- Revoked editor is denied on next request.
- Concurrent updates use optimistic concurrency in production.

## Sharing
- Owner grants Read.
- Owner grants Edit.
- Owner changes Read to Edit and vice versa.
- Owner revokes grant.
- Viewer/editor cannot grant or revoke.
- Unknown or inactive recipient is rejected.
- Duplicate grants are updated safely.
- Grant/revoke action is audited.

## Audit
- Upload, read, download, edit, delete, grant and revoke create events.
- Denied read/download/edit/delete attempts create denial events.
- Actor, document, action, result and timestamp are correct.
- Non-admin cannot see unrelated private audit events.
- Audit data cannot be updated/deleted by the runtime DB role.
- Hash chain is verified against an independently stored checkpoint.

## Search
- Search by filename, owner, category and date.
- Empty result shows an empty state.
- Search never returns unauthorized documents.
- SQL injection strings are treated as data.
- Pagination and sort limits are enforced.

## UI and deployment
- Login and logout work.
- Responsive layouts work on mobile and desktop.
- Loading, empty and error states are visible.
- Browser refresh handles session expiry.
- Fresh deployment and database initialization work.
- Health/readiness endpoints reflect dependency status.
- Backup restore is tested.
